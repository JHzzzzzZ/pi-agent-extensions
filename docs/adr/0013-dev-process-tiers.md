# 开发流程分档：T1 无行为改动 / T2 小修 / T3 契约改动

Status: accepted（2026-10-12，general-todo#34；用户逐条确认：对齐门保留、尾部瘦身、T2 单轮换成本。第 1 轮跨厂商评审（`kimi-coding/k3-256k`）推翻了初稿的两条论断——实证主张与判据重叠——本文件为修订稿，修订点见「修订记录」）

AGENTS.md 原先明写「以下规则无例外」，一行注释与删一个插件走同一套产物——固定成本 = todo 条目 + 两段式 `claim`（含一次人工往返）+ 对齐文档 + 规格文档 + worktree + 实现/测试 + 跨厂商评审循环（≤3 轮）+ 四处同步 + 收口，落成 git log 里 6–8 个 commit、30–60 分钟 agent 时间，与改动大小无关。决定：按**不可逆性**分三档，判据看碰没碰契约面（不看行数），T2 免规格、评审单轮、全量测试留 merge 前；T3 全流程一字不减；T1（无行为改动）免 todo/对齐/规格/评审/worktree。

## 实证依据（近 400 个 commit，逐条 git 核对过）

- **对齐与规格重复**：对齐文档 68 份（统计时点：评审时的已提交树，含 4 份 `.reopened` 归档；不含本条自身与其后在途的对齐文档）/ 16 份规格（均值 67 行）——小改动里是两个文件说同一件事。
- **复评轮不是空转**（初稿在这里说错了，评审用 `git show` 证伪）：`55ef944` 是**第 2 轮**的真行为修复（目录锚点尾斜杠不归一 ⇒ 去重键不一致、同一内容注入两次）、`91c735f` 是**第 3 轮**的真行为修复（远端 `$HOME` 带尾斜杠 ⇒ `isWithinBase` 判 false ⇒ 相对路径远端注入**静默全灭**）、`884f503` 是**第 1 轮**的 P1 断行恢复 + 4 条 P2。
- **其余轮次的发现多是文档/计数/测试补强**：`b0d7c14`（补一条生产路径用例，第 2 轮）、`2728167`（README 测试数 113→114，第 4 轮）、`90fe7ff`（卡片过时计数，第 1 轮、属另一次 agent-team 评审）。
- **误带的 lock 漂移被揪出 3 次**（`4cb74dc`/`e138676`/`856d7bd`）：首轮的「范围外改动」检查保留，做法是 merge 前扫一眼 `git diff --stat`。

**修订后的结论**：复评轮**有真实收益**——它抓到过 P2 级行为 bug，其中一处（静默功能全灭）比多数首轮发现更严重。T2 单轮因此不是「零风险优化」，而是一次**经批准的显式取舍**：用「可能漏掉 P2 级行为 bug」换「每轮评审的分钟级与 token 级成本」，并配一条最低护栏（下文决定 3）。

## 决定

1. **三档判据**（AGENTS.md「改动分档」表为唯一权威）：T1 = 无行为代码且不碰契约/流程定义面；T2 = 行为代码只动**一个单元**（`src/extensions/<x>/`、`agent-manager/`、`.agents/skills/todo-cli/todo-cli/`，或根 `test/`、`tools/` 单文件含配套测试）且契约面零变化，允许同变更附带 T1 类文件；T3 = 其余一切（含跨两个以上单元）。T3 的「其余」兜底必须在权威表里也写出来——第 2 轮评审指出 ADR 有兜底而 AGENTS.md 表没有，形成「无档可落」盲区（`agent-manager/` 这类根级工具的小修三档都不命中）。
2. **从严取档**：同时满足多档时 T3 > T2 > T1。初稿的 T1 无排除项，与 T3 撞车（`docs/cross/x.md`、AGENTS.md 的改动会同时满足两档）——已修：T1 明文排除 `docs/cross/`、`AGENTS.md`、`docs/adr/`、`CONTEXT.md`、`GOAL.md`。
3. **T2 评审单轮 + 行为面护栏**：首轮只处理 P1/P2；reviewer 必须显式回答「有无首轮未覆盖的**行为面**疑虑」（有则按 P1 处理，并加评一轮：加评轮内新冒出的 P1/P2 一并处理即止，T2 总轮数 ≤2）；处理完即 merge。「reviewer 是否回答过行为面」是可事后检查的留痕要求。
6. **记账类提交视同 T1**：只碰 `todos/*.json` / `todos/align/*.md` 的登记、`claim`/`align`、`complete` 类提交（含 `chore(todos):` 前缀的收口）不进定档——它们是红线 1/4 要求的主干动作，按表落到 T3 会与「主干工作区做 `todos/` 登记」直接冲突（第 3 轮评审以此前的 `23da914`/`7d29492` 为反例指出该盲区）。
4. **T1 免 worktree 与全量测试门**：文档/注释改动直接在主干提交（历史先例：`23930d4`/`7829012` 这类 docs 提交），但既有套件不得变红。
5. **复评护栏不变的是 T3**：≤3 轮 + 预算上限，一字不减。

## Considered Options

- **整块免掉 T2 评审**：最省，但 `55ef944`/`91c735f` 两处行为 bug 会进主干——否决。砍循环，不砍首轮。
- **维持「终轮无新意见」循环**：安全但贵（实证：第 2–4 轮约 7 个 commit 里 2 个真修复、其余是补强）——T3 保留，T2 改为单轮 + 行为面护栏（选定）。
- **按 diff 行数分档**（如 ≤50 行算小）：行数是坏代理——`context.ts` 5 行的尾斜杠归一能改掉远端路径语义；碰没碰契约面才是真信号——否决。
- **T 档写进 todo JSON（新字段 `tier`）**：CLI 要动 schema、加迁移与门禁，收益仅是展示；档位写进对齐文档正文即可留痕——否决（YAGNI）。
- **T2 免对齐（登记即 aligned）**：用户明确否决——返工成本在开工前最低，对齐门正是为此存在；省的是尾部，不是头部。
- **T2 免 worktree**：worktree 成本秒级，而多会话并行有真实互踩事故（general-todo#16）——否决，红线 4 对 T2/T3 保留。

## Consequences

- 红线编号 1–11 不变（`docs/` 下 19 个含「红线」引用的文件里约 14 个按号引用）：只加档位措辞，不重排；红线抬头原有的「与其他考量冲突时以本节为准」保留，并补「本节内部冲突按 T3 > T2 > T1」。
- 档位不进 `todos/*.json`、不进 todo CLI 命令面：无 schema 迁移，`align` 结构校验不变（对齐文档仍四小节）。
- T2 判据从「只动单个扩展目录」放宽到「**行为代码**只动单个单元 + 允许附带 T1 类文件」——这是对用户批准口径（对齐文档验收标准 1，已随本条落盘于 `todos/align/`）的**落地偏差**：不放宽则任何遵守红线 6/7（同步卡片 + README + 版本号 + lock）的真实代码改动都掉出 T2，T2 形同虚设。偏差由第 1 轮评审点出，此处登记。
- 本次变更**自身按表属 T3**（改流程本身）：免 spec 是唯一偏差（经用户同意；红线 3 对本变更不输出 `docs/specs/` 文件），评审则按 T3 口径走满 3 轮（一轮改实证 + 判据边界、二轮补盲区与锚点、三轮清残留）；「3 条真实小改动按 T2 走」的剂量测试从下一条真实改动开始，证伪标准 = 是否出现「首轮未提、复评才会发现的行为面问题」。
- 红线 8/9/10 全档适用；T3 的评审护栏（≤3 轮 + 预算上限）不变。
