# 开发流程分档：T1 无行为改动 / T2 小修 / T3 契约改动

Status: accepted（2026-10-12，general-todo#34；用户逐条确认：对齐门保留、尾部瘦身、T2 单轮不复评）

AGENTS.md 原先明写「以下规则无例外」，一行注释与删一个插件走同一套产物——固定成本 = todo 条目 + 两段式 `claim`（含一次人工往返）+ 对齐文档 + 规格文档 + worktree + 实现/测试 + 跨厂商评审循环（≤3 轮）+ 四处同步 + 收口，落成 git log 里 6–8 个 commit、30–60 分钟 agent 时间，与改动大小无关。决定：按**不可逆性**分三档，判据看碰没碰契约面（不看行数），T2 免规格、评审单轮、全量测试留 merge 前；T3 全流程一字不减；T1（无行为改动）免 todo/对齐/规格/评审。

## 实证依据（近 400 个 commit）

- **对齐与规格重复**：70 份对齐文档（中位 50 行）与 16 份规格（均值 67 行）内容大面积重叠——小改动里是两个文件说同一件事。
- **真修复全在第 1 轮**：`55ef944`（目录锚点尾斜杠归一，`context.ts` +5）、`884f503`（P1 断行恢复 + 4 条 P2）、`91c735f`（错误码透传），diff 均 5–15 行。
- **第 2–4 轮全是文档/计数/测试补强**：`2728167`（README 测试数 113→114）、`90fe7ff`（卡片「17 套件」过时计数）、`7829012`（注释说反）、`b0d7c14`（补一条生产路径用例）。→ 首轮值钱，复评不值钱。
- **另有 3 次「误带 lock 漂移」被揪出**（`4cb74dc`/`e138676`/`856d7bd`）：首轮的「范围外改动」检查保留，做法是 merge 前扫一眼 `git diff --stat`。

## Considered Options

- **整块免掉 T2 评审**：最省，但上列三个真行为修复都会漏到用户手里——否决。砍循环，不砍首轮。
- **按 diff 行数分档**（如 ≤50 行算小）：行数是坏代理——`context.ts` 5 行的尾斜杠归一能改掉远端路径语义；碰没碰契约面才是真信号——否决。
- **T 档写进 todo JSON（新字段 `tier`）**：CLI 要动 schema、加迁移与门禁，收益仅是展示；档位写进对齐文档正文即可留痕——否决（YAGNI）。
- **T2 免对齐（登记即 aligned）**：用户明确否决——返工成本在开工前最低，对齐门正是为此存在；省的是尾部，不是头部。
- **T2 免 worktree**：worktree 成本秒级，而多会话并行有真实互踩事故（general-todo#16）——否决，红线 4 全档保留。

## Consequences

- 红线编号 1–11 不变（`docs/` 下 19 个文件按号引用）：只加档位措辞，不重排。
- 档位不进 `todos/*.json`、不进 todo CLI 命令面：无 schema 迁移，`align` 结构校验不变（对齐文档仍四小节）。
- T2 的对齐文档「范围」小节承担原规格的「不做什么」职责——写不好就没有别的兜底。
- T1 靠 commit message 首行 `[T1]` 标记留痕（无 todo 条目、无收尾报告），便于事后抽查是否越档。
- 红线 4/8/9/10 全档适用、不减免；T3 的评审护栏（≤3 轮 + 预算上限）不变。
- 本变更自身即第一个剂量样本：走 T2 尾部（免 spec、单轮评审、全量测试留 merge 前）。
- 剂量测试计划：接下来 3 条真实小改动按 T2 走，统计「漏掉的问题是否都在首轮被抓住」；漏了就升档（回到 T3 口径），链路上限只有实际数据能证伪。
