# jev-safe-gate 真机验收清单（pi 1.0.1）

> 给用户执行：本清单里的行为**未经真机验证**，扩展的自动测试只覆盖到宿主接缝（fake 分类器 / fake UI）。
> 前置：把 `src/extensions/jev-safe-gate/` 复制到 `~/.pi/agent/extensions/`（或包安装后 `pi update`），Pi 内 `/reload`。

## 0. 准备

- 确认分类器可用：本扩展走内置 `typesafe/jev-latest`（不需要 API key 录入）。若 `typesafe` provider 在本机没有可用凭据，第 1、2 项会走第 3 项的 fail-open 路径——这本身也是必验项。
- 选一个可丢弃的目录做实验场（例：`/tmp/jev-gate-probe`），别在真实工作区里跑 `rm -rf`。

## 1. 候选命令 → 拒绝 → 被拦

1. 让 agent 执行：`rm -rf /tmp/jev-gate-probe`（先 `mkdir` 出来，命令文本要真的命中候选）。
2. 期望：弹出确认框，标题含「Jev 风险判断」，正文里能看到**命令原文**；状态条此时**不该**出现 `⚠ jev 放行N`。
3. 选「拒绝」。
4. 期望：这次 bash 调用被阻止（转录里是工具被拦下的结果，命令**没有执行**——`/tmp/jev-gate-probe` 仍在）。
5. 期望：模型收到的理由不含命令原文（静态模板）。

## 2. 候选命令 → 同意 → 执行

1. 同一条命令再来一次，这次选「同意」。
2. 期望：命令**原样**执行（`/tmp/jev-gate-probe` 被删掉）；转录里的命令与请求完全一致（无追加参数、无改写）。

## 3. 非候选命令 → 无感

1. 让 agent 跑几条日常命令：`ls`、`npm test`、`git status`。
2. 期望：不弹框、状态条无 `jev` 段、无可感知延迟（门的候选筛是纯正则）。

## 4. 分类器不可用 → 可观测地放行（fail-open 的补偿要求）

任选一种制造不可用：临时让 `typesafe` 无凭据 / 断网 / 或把 `PI_SOLO_MODE_FILE` 之类无关项排除后重试第 1 项命令。

1. 触发一条候选命令。
2. 期望：**放行**（命令照常执行），并且
   - footer 出现 `⚠ jev 放行N（原因）`（原因短标签如 `无分类器` / `报错` / `超时`）；
   - 本会话首次放行弹一次 notify（含原因码）；
   - headless（`pi -p "…"` / `--mode json`）时 stderr 有一行 `[jev-safe-gate] fail-open #N reason=…`。
3. 期望：门**不静默失效**——这条是验收硬要求，看不到任何痕迹即算失败。

## 5. solo 豁免

1. `/solo:on`（或 `pi --solo` 启动）。
2. 重复第 1 项候选命令。
3. 期望：**不弹框**、状态条无 `jev` 段、无 classify（无延迟）——solo 开启时本门完全不介入。
4. `/solo:off` 后再来同一条命令：期望恢复弹框（豁免只跟 solo 状态走）。

## 6. 只加摩擦（不绕过既有门）

1. 同一条候选命令，在一次「Jev 判定安全」（不弹框）的情形下观察：其它审批门/宿主的确认行为与**没有本扩展时一致**（本扩展只是可能多弹一次框，绝不替谁放行、绝不改命令）。
