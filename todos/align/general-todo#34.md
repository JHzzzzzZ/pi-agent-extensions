# general-todo#34 开发流程分档（T1/T2/T3）

## 意图

用户 2026-10-12 提出「对于一个小改动来说，这个开发流程是不是太重了」。核对现状后确认成立：AGENTS.md 明写「以下规则无例外」，一行注释与删一个插件走同一套产物——一次改动固定成本为 todo 条目 + 两段式 `claim`（含一次人工往返）+ 对齐文档 + spec 文档 + worktree + 实现/测试 + 跨厂商评审循环（≤3 轮）+ 四处同步 + 收口，落成 git log 里 6–8 个 commit、30–60 分钟 agent 时间，与改动大小无关。

实证（近 400 个 commit）：70 份对齐文档（中位 50 行）与 16 份规格（均值 67 行）内容大面积重叠；12 个「评审第 N 轮」修复 commit 里，**真行为修复全部出现在第 1 轮**（`55ef944` 尾斜杠归一、`884f503` P1 断行恢复、`91c735f` 错误码透传，diff 均 5–15 行），第 2–4 轮清一色是文档/计数/测试补强（`2728167` README 测试数 113→114、`90fe7ff` 卡片过时计数、`7829012` 注释说反）。

结论：**首轮评审值钱，复评不值钱；spec 对小改动是复述；全量测试每档都要，但不必每次改动都付**。

## 范围

**做什么**

1. 新增 `docs/adr/0013-dev-process-tiers.md`：三档定义（T1/T2/T3）、机器可查判据、逐档产物清单、实证依据与裁决记录。
2. AGENTS.md 改动（编号保持不变——库外文档大量按号引用）：
   - 红线段抬头：把「以下规则无例外」改为分档口径（T1 明文豁免，见档位表）。
   - 新增「改动分档」小节：三档判据 + 逐档允许/豁免清单，紧邻需求生命周期（1→7）。
   - 红线 3 加档位：T2 免 spec（对齐文档即规格），T3 照旧。
   - 红线 7 加档位：T2 开发中跑受影响套件 + typecheck，全量测试留 merge 前一次。
   - 红线 11 加档位：T2 单轮评审、只处理 P1/P2（P3 记 `todos/` 不阻塞）、处理完即 merge，不触发复评；T1（无行为改动）免评审；T3 维持「终轮无新意见 + ≤3 轮 + 预算上限」。
3. `docs/INDEX.md` 登记 ADR-0013 的路由行。

**不做什么**

- 不动 `todos/` 状态机与对齐门：两段式 `claim`（含人工确认）**原样保留**——用户明确要求 T2 仍必须对齐，不允许「登记即 aligned」。
- 不改 todo CLI 命令面与 JSON schema：**不新增 `tier` 字段**（避免存储迁移）；档位写在 AGENTS.md 判据里、需要留痕时写进对齐文档正文。
- 不动红线 4（worktree）、8（仓库边界）、9（命令超时）、10（团队方案审批）。
- 不改评审的护栏（最大轮数/预算）——那是 T3 的护栏，只给 T2 换口径。
- 不动 T3 的任何环节。

## 验收标准

1. AGENTS.md 出现三档判据与逐档产物清单，判据可机器核对：T1 ⇔ 改动不含行为代码（仅注释/文档/版本号/lock）；T2 ⇔ 只动单个 `src/extensions/<x>/` 且 `docs/cross/`、状态键、工具注册面、错误码集、消息键、公开 API 零变化；其余为 T3。
2. 红线编号 1–11 不变，外部文档中按号引用（`docs/` 下 19 个文件）全部继续成立。
3. `docs/adr/0013-dev-process-tiers.md` 落盘且被 `docs/INDEX.md` 路由；ADR 记明实证数据与「T2 单轮不复评」的裁决。
4. 本变更自身即第一个剂量样本：按 T2 尾部执行（免 spec、单轮评审、全量测试留 merge 前），把实际成本写进 ADR 的落地注记。
5. `npm run test:all` 全绿 + pwr `npm run typecheck` 零错误（docs-only 变更，用于确认无回归）。
