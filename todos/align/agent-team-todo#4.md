# agent-team-todo#4 与各 agent 动态对话：同一成员的多轮追问

## 意图

让发起者能对着**同一个成员**多轮追问与纠偏，而不是每轮重开一单。当前派单是「整单派发」：成员是一次性子进程（`dispatch.ts` 的 `["--mode","json","-p","--no-session"]`），跑完交结果回 leader；发起者没有对单个成员的多轮通道。

条目里留的进展（count-duet 1-10 跑通、1-1000 超预算）是自造压力用例，不是真实工作负载——本轮据此收敛口径。

**用户场景（推断，待确认）**：一轮 run 跑完后，对某个成员追问「第 3 个文件为什么这么改」，并要求它按新要求改那一处，**同一条对话线继续**、成员记得前文。

## 范围

做什么：

- 对话身份：同一成员在同一对话线内可被多轮派发，前文可见（转录里是同一条线，不是若干互不相干的 run）。
- 机制默认：每轮把「最近 N 轮前文 + 摘要头」注入成员 prompt；成员保持一次性子进程，不引入常驻进程或 session 状态。
- 路由复用既有面：viewer 输入框的 `chat` 队列与目标（`targetLabel`）已能指向具体 actor，不新造派单通道。
- 成本计入已有 run 级预算（`types.ts` 的 dispatch / member-run / cost 三类上限）。
- 终止沿用 `/team:stop` 与超时语义；保留「leader 是唯一中枢」不变量（无成员间旁路）。

明确不做什么：

- 不做 `#5` 全页 viewer、不做 `#68` 长回答输入（两条保持 open，交互面维持现状）。
- 不把成员改成带 session 的续写进程（去掉 `--no-session` 属 Round 3 备选，需先拿成本数据）。
- 不做成员间消息板 / `@` 旁路路由（`#50` 独立条目）。
- 不改 leader 拆解与派发语义（多轮对话不改变「leader 是唯一中枢」）。

## 验收标准

- 同一成员至少 3 轮往返：第 3 轮的回答能引用第 1 轮的内容（证明前文注入确实生效）。
- 每轮成本落转录并计入 run 级预算；超预算按既有语义收口（不新增预算类型）。
- 交互面维持现状：overlay viewer 输入框 + 主会话，无新增 UI 组件。
- 测试：对话线的前文注入内容与预算计数有单测锁定；宿主级渲染测试不动。
- README 与 `docs/extensions/agent-team.md` 同步用法与限制（含「前文注入」的成本特征）。
- 全量测试 + `npm run typecheck` 零错误。
