# 对齐：remote-tools-todo#14 — 同一文件经 `.`/`..` 别名重复注入，且块标题未归一化

- 日期：2026-10-11（UTC）· 参与：用户（真机实测发现）+ agent（根因核实、设计）
- 状态：**已对齐**（用户选定「四件打包一个分支」）

## 意图

用户真机实测：`read /tmp/dcB/x.txt`（正常注入 `/tmp/dcB/AGENTS.md`）之后，再 `read /tmp/dcB/../dcB/x.txt` ⇒ **同一份 `AGENTS.md` 被再注入一次**，块标题是 `Loaded user@localhost:/tmp/dcB/../dcB/AGENTS.md`。

**根因**：远端上下文的去重键与块标题都用「解析后但**未归一化**」的路径字符串。`.`/`..` 一变就是新键 ⇒ 重复注入（浪费上下文、污染转录），标题也不是真实路径。

模型与 codemode 写带 `..` 的路径很常见，所以这不是边角情形。

## 范围

**做什么**（共享设计见 `todos/align/remote-context-v2-design.md`）

1. 解析出远端绝对路径后立刻 `posix.normalize`，再用于祖先链遍历与帧里的 `<path>`（`/` 根与尾斜杠的既有归一保持不动）。
2. 消费方不必改：它的去重键与块标题都取自帧里的路径，提供方一处归一即同时修好。

**明确不做什么**

- 不在消费方加「二次归一化」的防御性代码——同一份路径只在提供方一处产出，两边都归一反而让「谁负责」变模糊。
- 不处理符号链接指向同一文件的情形（需要 `realpath`，多一趟 ssh 或额外命令；判据是「路径字符串归一」，不是「文件身份」）——记为已知边界。

## 验收标准

1. **不重复注入**：同会话先 `read <dir>/x.txt` 再 `read <dir>/../<base>/x.txt` ⇒ 第二次**不再注入**（去重键相同）。
2. **标题是真实路径**：任何一次注入的块标题都是归一化后的绝对路径，不含 `.`/`..`。
3. **归一正确性单测**：`/a/b/./c`、`/a/b/../b/c`、`/a/../../c`、`/`、尾斜杠各形态的期望输出逐一断言（含 `posix.normalize` 对 `..` 越界到根的行为）。
4. **与 `#7` 的 fail-closed 不冲突**：归一化后仍对 `~` 开头等非法形态报既有错误码。
5. **真机对照**：真实 `pi` + 真实 ssh，按上面 1/2 各跑一次（用完删除远端临时目录）。
6. 单测 + typecheck 双绿；全仓 `test:all` 除已知并发抖动外全绿。
7. 跨厂商独立评审（红线 11）逐条处理到某轮无新意见。
