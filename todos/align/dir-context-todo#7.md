## 意图

`#6`（远端目录上下文自动注入）的验收过程中，用户按真实触发条件造场景：远端 `AGENTS.md` **存在但 `chmod 000`**，然后 `read` 同目录文件。观察到的三连：

1. **注入了一个空内容的块**（noise）：
   ```
   Loaded user@localhost:/tmp/dchk2/AGENTS.md
   <dir-context remote="user@localhost" path="/tmp/dchk2/AGENTS.md">
                                       ← 空
   </dir-context>
   ```
2. **提示行被抑制** —— 使用者会误以为「远端那个目录没有约定文件」。
3. **该路径被标记为「已注入」** —— `chmod 644` 之后同一会话再 `read` 同一文件只返回原文，真内容这一会话内再也进不来（要新会话）。

**根因（agent 核实，与用户判断一致）**：`remote-tools/context.ts` 的 `buildContextCommand` 用 `[ -f "$f" ]` 判存在——`-f` 只 stat，**不看读权限**；随后 `cat "$f"` 失败只往 stderr 写，stdout 上照样发出 `path\0` + `\0`（内容为空）。`parseContextFiles` 无法区分「真的空文件」与「cat 失败」，于是把空帧当合法文件收下 ⇒ 满足上面三连。

## 范围

**做什么**

1. **提供方（`remote-tools/context.ts`）**：
   - `buildContextCommand` 每级分两支：`[ -f "$f" ]` 且 `[ -r "$f" ]` ⇒ 正常发 `path\0` + `cat` + `\0`；`-f` 真而 `-r` 假 ⇒ 发一个**带 SOH（`\x01`）前缀的标记帧** `\x01<path>\0\0`（真实路径帧恒以 `/` 开头，不可能撞车）。
   - `parseContextFiles` 返回值从 `RemoteContextFile[]` 改成 `{ files, unreadable }`——后者是「存在但读不出」的路径列表。
   - `createRemoteContextCapability`：**只要链上出现任一个读不出的候选 ⇒ 整条请求 `ok: false`**（fail-closed，绝不静默少注入），错误码沿用 `REMOTE_CONTEXT_FAILED`。
2. **消费方**：无需改动——`ok: false` 走既有的三态逻辑：`unavailable` ⇒ 退回那行提示 **且不把任何路径标记为已注入**（下次触碰还能重试）。
3. **测试**：命令拼装（`-r` 分支 + 标记帧）、标记帧解析（进 `unreadable`、不进 `files`）、能力层 `ok:false`、以及「真·空文件仍按空文件处理」（不能把合法空文件误判成读不出）。
4. **文档**：契约卡补「存在但读不出 ⇒ 整条请求失败」的约定与标记帧；`docs/extensions/remote-tools.md` 与 `docs/extensions/dir-context.md` 补一句。

**明确不做什么**

- 不改「真·空文件」的既有语义（空的 `AGENTS.md` 仍注入一个空块——与本地口径一致）。
- 不做「部分成功」（一个目录读不出、另一个能读 ⇒ 仍按整条失败处理）：`#6` 的立场是绝不静默少注入；读不出的约定文件是**配置事故**，应当让使用者看见而不是悄悄跳过。
- 不在消费方加特殊分支（提示与不标记已注入都由既有三态承担）。

## 验收标准

1. **不再注入空块**：远端某级 `AGENTS.md` 存在但不可读 ⇒ 结果里**没有**该路径的 `Loaded` 块。
2. **提示行出现**：同一次结果里出现那行静态提示（不是静默）。
3. **不标记已注入**：`chmod 644` 之后**同一会话**再触碰同一目录 ⇒ 这次能真的注入内容（不需要新会话）。
4. **真·空文件不误判**：远端 `AGENTS.md` 是 0 字节 ⇒ 仍按空文件处理（`files` 里出现它、`unreadable` 为空）。
5. **混合链 fail-closed**：链上外层可读、内层不可读 ⇒ 整条 `ok:false`（不注入外层的部分内容）——这一条是**对齐时的判断**，见下节。
6. 单测 + typecheck 双绿；全仓 `test:all` 除已知并发抖动外全绿。
7. 真机对照：真实 `pi` + 真实 ssh 到本机 WSL，在远端 `/tmp` 造一个 `chmod 000` 的 `AGENTS.md`（用完删除）——对照 `#6` 的既有场景，逐条核对上面 1/2/3。
8. 跨厂商独立评审（红线 11）逐条处理到某轮无新意见。

  所以 agent 的方案是：读不出时发一个**带 SOH 前缀的标记帧**，让「存在但读不出」在协议层可区分；提供方据此回 `ok: false`。

  - **(B) 只用 `[ -r ]` 丢帧**（你原建议的字面实现）：空块消失、不标记已注入，但**仍然没有提示行**——等于把「误以为没有约定文件」换成「这次运气好，没看见而已」。选这条的话我会把「读不出 = 静默跳过」写进契约卡当作已知边界。
